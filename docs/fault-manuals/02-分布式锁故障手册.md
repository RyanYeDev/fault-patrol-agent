# 分布式锁故障手册

> 知识标签：`fault-handbook` | 适用场景：重复执行、锁失效、锁等待超时

## 故障现象

- 定时任务在多个实例上同时执行（锁未生效）
- 业务接口偶发重复处理（如重复发券、重复扣款）
- 大量线程阻塞在锁等待，接口超时
- 锁释放异常导致业务长时间无法执行

## 排查步骤

1. **Redis 锁检查（Redis 工具）**
   - 扫描锁键：`redisScanKeys('lock:*')`
   - 查看锁键信息：`redisGetKeyInfo('lock:xxx')` —— 核对 value（是否本机实例持有）、TTL（是否合理，一般 10~30 秒）
   - 若 TTL 为 -1（永不过期），说明续期/释放逻辑异常，锁已泄漏

2. **指标分析（Prometheus）**
   - 锁等待耗时：`histogram_quantile(0.99, rate(lock_acquire_duration_seconds_bucket[5m]))`
   - 锁获取失败率：`rate(lock_acquire_failures_total[5m])`
   - 实例数核对：确认服务实例数是否与预期一致（多实例 + 非分布式锁 = 重复执行）

3. **链路分析（Jaeger）**
   - 检索持锁时间过长的 span，定位业务在锁内做了什么重操作
   - 关注「释放锁」span 是否缺失（异常路径未释放）

4. **业务数据核对**
   - 核对重复执行产生的业务记录（如重复发放的券、重复生成的单据）

## 常见根因

| 根因 | 特征 |
|------|------|
| 锁 key 不一致 | 各实例使用了不同的锁 key，互不排斥 |
| 未设置过期时间或续期失败 | 持锁实例宕机后锁永久不释放 |
| 释放了别人的锁 | 未校验 value 归属即 DEL，锁链断裂 |
| 锁粒度过粗/锁内操作过重 | 锁等待队列堆积，接口超时 |
| 时钟漂移影响过期判断 | 多实例时间不同步，提前释放 |

## 处置建议

1. 手动删除泄漏的锁键（确认无业务在执行后）
2. 紧急情况下重启持锁异常实例，让锁自然过期
3. 修复释放逻辑：必须校验 value 归属后再释放（Lua 脚本原子完成）
4. 锁内重操作移出锁外，缩小锁粒度
5. 检查续期任务（Watch Dog）是否正常运行

## 预防措施

- 统一封装分布式锁组件：key 规范 + 过期兜底 + value 归属校验 + 自动续期
- 锁等待时间、持锁时间纳入监控告警
- 定期演练「持锁实例宕机」场景，验证锁自动恢复
