# 库存扣减故障手册

> 知识标签：`fault-handbook` | 适用场景：下单失败、库存扣减异常、超卖/少卖

## 故障现象

- 下单接口返回「库存不足」，但库存页面显示有货
- 库存扣减成功但订单创建失败，库存无法回补
- 大促期间出现超卖（扣减结果为负数）
- 库存扣减接口响应时间突增

## 排查步骤

1. **业务数据核对**
   - 查询订单表：`SELECT * FROM orders WHERE order_id='xxx'`
   - 查询库存表：`SELECT * FROM inventory WHERE sku_id='xxx'`，核对 `stock`、`locked_stock`（锁定库存）与 `version`（乐观锁版本号）
   - 核对库存流水表 `inventory_flow`：扣减流水是否完整、幂等键是否重复

2. **指标分析（Prometheus）**
   - 库存服务 QPS/错误率：`rate(inventory_service_requests_total{status="error"}[5m])`
   - 扣减接口耗时：`histogram_quantile(0.99, rate(inventory_deduct_duration_seconds_bucket[5m]))`
   - JVM/线程池水位：`jvm_threads_peak_threads`、`tomcat_threads_busy_threads`

3. **链路分析（Jaeger）**
   - 检索 inventory-service 的慢链路，定位扣减 SQL / 锁等待耗时
   - 关注「扣减成功但后续失败」的 span 序列，判断事务边界是否正确

4. **中间件检查**
   - Redis：检查库存缓存 key（如 `stock:sku:{id}`）的值与 TTL；Lua 脚本扣减是否存在 `-1` 回退逻辑缺失
   - MQ：检查库存回补消息队列是否存在积压

## 常见根因

| 根因 | 特征 |
|------|------|
| 缓存与数据库库存不一致 | Redis 中有库存、DB 中已无库存；缓存更新失败未重试 |
| 乐观锁重试不足 | 大促并发下 `version` 冲突大量失败，重试次数过少 |
| 事务边界错误 | 扣减与订单创建不在同一事务或补偿缺失，导致库存悬挂 |
| Lua 脚本缺陷 | 原子扣减脚本未处理 `result < 0` 分支，出现负库存 |
| 回补消息丢失 | MQ 消息未持久化或消费者未 ack，库存长期锁定 |

## 处置建议

1. 立即核对 DB 与缓存库存差异，人工修正差异库存
2. 对失败订单执行库存回补（走幂等回补接口）
3. 若为乐观锁冲突：临时提升重试次数并评估是否需要切换「预扣 + 异步确认」方案
4. 修复 Lua 脚本负数分支并灰度发布
5. 回补 MQ 队列积压时，先扩容消费者再放行消息

## 预防措施

- 库存变更全链路流水对账（DB 流水 vs 缓存 vs 订单）
- 缓存更新失败接入重试队列，防止静默漂移
- 定期演练库存回补与对账脚本
