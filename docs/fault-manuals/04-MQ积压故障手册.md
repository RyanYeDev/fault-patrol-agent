# MQ 积压故障手册

> 知识标签：`fault-handbook` | 适用场景：消息积压、消费延迟、消息丢失

## 故障现象

- 队列消息积压数量持续上涨（ready 消息数远超正常水位）
- 业务处理延迟增大（下单后长时间不发货、日志延迟等）
- 消费者频繁重启/崩溃
- 死信队列快速增长

## 排查步骤

1. **MQ 检查（RabbitMQ 工具）**
   - 队列积压概览：`mqOverview()` 查看集群级消息速率与队列总量
   - 队列列表：`mqListQueues()` 定位积压队列（messages_ready 大、consumers 为 0 或偏少）
   - 单队列详情：`mqQueueInfo('queue_name')` 查看积压数、消费者数、发布/消费速率
   - 连接与消费者：`mqListConnections()` / `mqListConsumers()` 确认消费者是否存活、prefetch 是否合理

2. **指标分析（Prometheus）**
   - 消费速率 vs 生产速率：`rate(rabbitmq_queue_messages_published_total[5m])` 与 `rate(rabbitmq_queue_messages_delivered_total[5m])`
   - 消费者业务错误率：下游服务错误率指标

3. **链路分析（Jaeger）**
   - 检索消费者处理链路的慢 span，定位是业务处理慢还是依赖服务超时

4. **容器检查（Container 工具）**
   - 查看消费者实例状态与日志：`containerStatus('consumer')`、`containerLogs('consumer', 200)`
   - 检查 CPU/内存是否被打满：`containerStats('consumer')`

## 常见根因

| 根因 | 特征 |
|------|------|
| 消费者宕机/缩容 | consumers=0 或骤降，积压直线上升 |
| 消费逻辑变慢 | 消费速率骤降，下游依赖超时（DB/第三方） |
| 消息风暴 | 生产速率异常放大（上游批量重放、定时任务异常） |
| prefetch 过低 | 单个消费者吞吐上不去，积压与消费并存 |
| 死信未处理 | 坏消息反复入队，拖慢整体消费 |

## 处置建议

1. 消费者宕机：优先恢复消费者实例，并视积压量临时扩容
2. 消费慢：定位慢依赖（如 DB 慢 SQL），临时降级非核心逻辑；提高 prefetch 与并发消费数
3. 消息风暴：上游暂停生产（关闭定时任务/降级入口），防止积压失控
4. 死信堆积：暂停死信重投，坏消息移入临时队列，修复后重放
5. 紧急兜底：积压严重时启用「扩容 + 多消费者临时集群」快速消化

## 预防措施

- 队列积压水位监控告警（绝对阈值 + 增长速率）
- 消费者健康检查与自动扩容策略
- 死信队列监控与告警，坏消息人工介入规范
- 定期压测消费能力，明确容量水位线
